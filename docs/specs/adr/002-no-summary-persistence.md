# ADR-002: セッション要約を永続化しない

- **ステータス**: Accepted
- **決定日**: 2026-07-09

## コンテキスト

セッション詳細画面には「要約実行」があり、`claude -p`（haiku 固定）でセッションの
直近要約・全体要約を生成する。この要約結果をどこに保存するかを決める必要があった。
候補は (a) メモの body へ下書きとして流し込む、(b) メモに summary 専用フィールドを足す、
(c) 保存せず表示のみ。

メモのスキーマは「ユーザー入力 3（title/tags/body）+ 自動記録 6」で確定しており、
body は人の自由記述と定義されている。

## 決定

**要約はディスクに保存しない。アプリ常駐中のみ生きるメモリキャッシュ
（キー: セッション ID × 要約範囲）だけを持つ。**

## 理由

- 「要約は使い捨ての表示情報、残したい内容はユーザーがメモ本文に書き移す」という整理。
  機械生成テキストがメモに自動で入り込むと「メモは人が書くもの」というモデルが崩れる
- メモフォームからセッション詳細を開いても下書きが保持される作りになっており、
  「要約を見ながらメモ本文に要点を書き移す」フローで永続化の必要をカバーできる
- キャッシュの目的は永続化ではなく、同じセッション詳細を開き直したときに
  `claude -p` を再実行しないこと（時間と API 利用料の節約）
- 「永続データはメモだけ」という単純さは、ストアの版管理・バックアップ・
  マシン間コピーをすべて memos.json 1 ファイルの話に保つ

## 影響

- アプリを終了すると要約は消える。再表示には再実行コスト（時間・利用料）がかかる
- 要約も残したくなったら、`updatedAt` 付きでメモとは別ファイルに保存する拡張になる。
  使ってみてから判断する（requirements.md 将来課題）
- 全体要約の fork セッションが `~/.claude/` に残る副作用は本決定とは独立で、
  プロンプト先頭のマーカー文字列による一覧除外で対処する
