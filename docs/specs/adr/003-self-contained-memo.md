# ADR-003: メモは復帰情報を自己完結で持つ

- **ステータス**: Accepted
- **決定日**: 2026-07-09

## コンテキスト

メモとセッションの紐付け方には 2 案あった。

1. メモは `sessionId` だけを持ち、タイトルやプロジェクトパスは表示のたびに
   `~/.claude/history.jsonl` から引く（正規化）
2. 復帰に必要な情報をメモ自体に記録する（スナップショット）

`history.jsonl` は Claude Code の内部ファイルであり、将来ローテート・形式変更・削除されうる。
アプリの前提として「アプリを消してもメモは残る」を掲げている。

## 決定

**復帰に必要な情報（`sessionId` + `projectPath`）と、セッションタイトル由来の初期値を持つ
`title` をメモ自体に記録する。フル・スナップショット（セッションメタデータ全体の抱き込み）は行わない。**

## 理由

- `history.jsonl` から該当セッションが消えた後でも、メモからの復帰
  （`cd <projectPath> && claude --resume <sessionId>`）が機能し続ける
- メモタイトルの初期値にセッションタイトルを自動入力する仕様が、
  実質的にタイトルのスナップショットを兼ねる。専用フィールドの追加は不要
- フル・スナップショットまでやるとデータ重複と更新整合の問題を先取りしてしまう。
  必要になってから `schemaVersion` を上げて拡張できる

## 影響

- 編集で変更できるのは `title` / `tags` / `body` のみ。
  `id` / `agent` / `sessionId` / `projectPath` / `createdAt` は不変とし、
  MemoStore の update はこの不変性を保証する（ユニットテスト対象）
- セッション実体が消えたメモは「復帰コマンドは組み立つが resume は失敗する」状態になりうる
  （主因は Claude Code の `cleanupPeriodDays`（デフォルト 30 日）によるセッション自動削除）。
  Swift 版はこれを注意画面の説明で利用者に伝える方式を取っており、Moost も踏襲する
