# ADR-004: 登録プロジェクトはエージェントを登録時に固定しない

- **ステータス**: Accepted
- **決定日**: 2026-07-20

## コンテキスト

新規セッションを起動するためのディレクトリを覚えておく「登録プロジェクト」機能を追加する。
既存のメモは `agent`（Claude Code / Codex）フィールドを持ち、1件のメモは1つのエージェントに
紐づく。登録プロジェクトも同様に、登録時にエージェントを固定するか、起動のたびに選ぶかの
2案があった。

## 決定

**登録プロジェクトはエージェントを登録時に固定しない。一覧行にエージェントごとの
アイコンボタン（Claude Code / Codex）を並べ、起動のたびにどちらで開くかを選ぶ。**

## 理由

- メモやセッションは実際にそのエージェントで行われた履歴から生成されるため `agent` が
  自然に決まるが、登録プロジェクトは「まだ何も実行していないディレクトリ」であり、
  そもそも紐づけるべきエージェントが存在しない
- 同じプロジェクトを Claude Code と Codex の両方で使い分けたい場合に、エージェントを
  切り替えるたびに再登録する手間がない
- 現状エージェントは2種類のみのため、行に2つのアイコンボタンを並べても行の幅を
  大きく圧迫しない。既存の「一覧行は基本1クリックで完結する」という UI 方針とも合う

## 影響

- 登録プロジェクトのモデルは `id` / `projectPath` / `createdAt` のみで、`agent` フィールドを
  持たない（メモのスキーマとは非対称になる）
- エージェントが3種類以上に増えた場合、アイコンボタンを並べる方式は行の幅を圧迫し始める。
  その時点でポップアップメニュー方式への変更を再検討する
