# Moost 要求・要件定義

- **ステータス**: ドラフト
- **作成日**: 2026-07-09
- **用語集**: [CONTEXT.md](./CONTEXT.md)

## 1. 背景と目的

Claude Code などの AI コーディングエージェント CLI はセッションを跨いで作業が続くが、
「あのセッションはどこまで進んだか」「どのセッションに戻ればいいか」を思い出す手段が乏しい。
`claude --resume` はあるが、セッション ID の特定とプロジェクトディレクトリへの移動を人が毎回やる必要がある。

Moost（Memo + Roost）は、セッションに人がメモ（タイトル・タグ・本文）を付けて記録し、
ワンクリックでターミナルを開いてセッションへ復帰できるようにするシステムトレイ常駐アプリである。

Swift 製の先行実装（claude-session-memo）が macOS で動作しており、
その知見（データ取得ロジック・既知のハマりどころ）を引き継いで Dart/Flutter で再構築する。
再構築の理由は [ADR-001](./adr/001-dart-flutter-over-swift.md) を参照。

## 2. スコープ

### 対象

- エージェント: **Claude Code のみ**（当面はこれだけを実装・テストする）
- 第 1 弾の OS: macOS（Flutter デスクトップ）
- OSS として公開する

### 将来対応（今は実装しないが、拡張できる作りにしておく）

- Codex CLI・Gemini CLI 等の他プロバイダー対応。
  `AgentAdapter` 抽象（5 章）で拡張口だけ確保し、adapter の追加実装は行わない
- Windows/Linux 対応

### 対象外

- エージェント側データ（`~/.claude/` 等）への書き込み。**読み取り専用**とする
- Swift 版先行実装のメモデータ（`~/.claude-session-memo/v1/memos.json`）からの移行機能
- セッション内容の全文検索・全文表示（一覧・タイトル・要約まで）
- メモのマシン間同期（保存先が単一 JSON なので、必要なら利用者が Git 等で自前管理できる）

## 3. 機能要件

### 3.1 直近セッション一覧

- `~/.claude/history.jsonl` を集約し、直近セッションを最新順に一覧表示する
- 各行に表示: セッションタイトル / プロジェクト / 最終更新日時
- 要約用フォークセッションはプロンプト先頭のマーカー文字列で一覧から除外する
- パースできない行は例外にせずスキップする（内部フォーマット変更でクラッシュしない）

### 3.2 セッションタイトルの自動導出

優先順に 3 段構えで導出する（詳細は [design.md](./design.md#セッションタイトルの導出) 参照）:

1. `history.jsonl` の集約（この時点ではタイトルなし、最終プロンプトのみ保持）
2. セッション JSONL 末尾の `ai-title` 行（Claude Code 自身が生成したタイトル）
3. なければ最終プロンプト先頭 50 文字で代用

### 3.3 メモ CRUD

- メモは 9 フィールド。**ユーザー入力 3 + 自動記録 6**

| 種別 | フィールド | 内容 |
|------|-----------|------|
| 入力 | `title` | メモタイトル。必須（空だと保存不可）。新規登録時はセッションタイトルが初期値として自動入力される |
| 入力 | `tags` | カンマ区切りで入力し、保存時に分割・トリム・空要素除去して配列で保存 |
| 入力 | `body` | 自由記述のメモ本文（複数行） |
| 自動 | `id` | メモ自体の UUID。同一セッションに複数メモを許容するため `sessionId` とは別に持つ |
| 自動 | `agent` | エージェント種別（第 1 弾は `claude-code`） |
| 自動 | `sessionId` | 対象セッションの ID（復帰コマンドに使う） |
| 自動 | `projectPath` | プロジェクトの絶対パス（復帰時の `cd` 先に使う） |
| 自動 | `createdAt` | 作成日時 |
| 自動 | `updatedAt` | 最終更新日時（編集のたびに更新） |

- 編集で変更できるのは `title` / `tags` / `body` の 3 つだけ。他は不変
- メモ削除は確認 UI を挟む（ダイアログではなくフォーム内インライン表示。
  別ウィンドウを出すとポップオーバーが閉じるため）
- 復帰に必要な情報（`sessionId` + `projectPath`）をメモ自体が自己完結で持つ。
  `history.jsonl` から該当セッションが消えた後でもメモからの復帰は機能する
  （[ADR-003](./adr/003-self-contained-memo.md)）

### 3.4 メモの保存

- 保存先: `~/.moost/v1/memos.json`（単一ファイル・人が読める JSON）
- エンベロープ形式:

```json
{
  "schemaVersion": 1,
  "memos": [
    {
      "id": "5F0A...",
      "agent": "claude-code",
      "sessionId": "77e31958-86fe-433e-b1dc-9d9059daa112",
      "title": "レコメンド移行の調査",
      "tags": ["peko", "調査"],
      "body": "external-api のプロキシ調査の続き。次は〜から再開",
      "projectPath": "/Users/user/IdeaProjects/works",
      "createdAt": "2026-07-08T10:00:00Z",
      "updatedAt": "2026-07-08T12:30:00Z"
    }
  ]
}
```

- アプリをアンインストールしてもメモは残る

### 3.5 セッション復帰

- 復帰コマンドを `cd <projectPath> && claude --resume <sessionId>` の形に組み立てる
- 復帰の入口は 3 つ: セッション一覧の行 / セッション詳細の「ターミナルで開く」 /
  **メモ（一覧・編集フォーム）の「ターミナルで再開」**。メモは復帰情報を自己完結で持つため、
  元セッションが一覧から消えていてもメモから復帰できる
- Terminal.app または iTerm2 を開き復帰コマンドを実行（macOS では osascript 経由。設定でターミナル切替）
- 各行に復帰コマンドのクリップボードコピーボタンを付ける
- `projectPath` にバッククォート等が含まれるケースのシェルエスケープを必ずテストする
- 制約: セッション実体は Claude Code の `cleanupPeriodDays`（デフォルト 30 日）で自動削除される。
  メモがあっても期限切れセッションには復帰できない場合があることを注意画面でユーザーに伝える

### 3.6 セッション要約

- セッション詳細画面から実行。モデルは haiku 固定。2 モード:
  - **直近要約**: 直近 N ラリーの抜粋を `claude -p` の stdin に渡す
  - **全体要約**: `claude -p --resume --fork-session` でセッション全体を要約
- 要約結果は**永続化しない**。アプリ常駐中のメモリキャッシュ（セッション ID × 要約範囲がキー）のみ
  （[ADR-002](./adr/002-no-summary-persistence.md)）
- 残したい要点は人がメモ本文へ書き移す。メモフォームからセッション詳細を開いても下書きは保持される
- 全体要約が生む要約用フォークセッションは、プロンプト先頭のマーカー文字列で直近セッション一覧から除外する

### 3.7 常駐 UI（フェーズ 2・macOS 先行）

- システムトレイ常駐（Dock アイコンなし）。トレイアイコンクリックでポップアップウィンドウ表示
- 画面: 直近セッション一覧 / メモ一覧 / **プロジェクト一覧（登録プロジェクト、3.8）** /
  メモ登録・編集フォーム / セッション詳細（要約実行） /
  注意画面（要約が API 利用枠を消費すること等の説明） / 設定
- 設定項目: ターミナル種別 / 直近セッション表示件数（5〜100、デフォルト 20） /
  `claude` コマンドのパス上書き（要約専用。空欄なら自動検出） / ログイン時自動起動
- 要約対象のラリー数（1〜20、デフォルト 1）は設定画面ではなくセッション詳細画面の
  ステッパーで変更し、永続化する
- 設定は `~/.moost/v1/settings.json`（人が読める JSON、全 OS 共通方式）に保存する。
  ただしログイン時自動起動だけは OS 管理とし、OS の実状態を正として毎回読む

### 3.8 登録プロジェクト

まだセッション履歴が1件もないディレクトリからでも新規セッションを開始できるよう、
ユーザーが明示的にディレクトリを登録しておく機能。メモとは異なりセッションに
紐づかず、`agent` も持たない（[ADR-004](./adr/004-project-agent-chosen-at-launch.md)）。
用語の詳細は [CONTEXT.md](./CONTEXT.md#language) の「登録プロジェクト」を参照。

- フィールドは 3 つ。**ユーザー入力 1（`projectPath`）+ 自動記録 2**

| 種別 | フィールド | 内容 |
|------|-----------|------|
| 入力 | `projectPath` | OS のフォルダ選択ダイアログで選んだディレクトリの絶対パス |
| 自動 | `id` | 登録プロジェクト自体の UUID |
| 自動 | `createdAt` | 登録日時 |

- 一覧の表示名は保存せず、`projectPath` の最後のディレクトリ名を表示のたびに導出する
- 「プロジェクト」タブの一覧上部に常設の「登録」ボタンを置き、押すと OS のフォルダ選択
  ダイアログが開く。同じパスの重複登録は防止しない
- 各行にエージェント（Claude Code / Codex）ごとのアイコンボタンを並べ、押すと
  そのエージェントで新規セッションを開始するターミナルコマンドを実行する
  （`cd <projectPath> && claude` 相当。`--resume` は付けない）
- 削除はメモと同じインライン確認 UI（「〈ディレクトリ名〉の登録を解除しますか？」+
  キャンセル/削除）
- 保存先: `~/.moost/v1/projects.json`（`memos.json` と同じエンベロープ形式）

```json
{
  "schemaVersion": 1,
  "projects": [
    {
      "id": "9C2B...",
      "projectPath": "/Users/user/IdeaProjects/moost",
      "createdAt": "2026-07-20T09:00:00Z"
    }
  ]
}
```

## 4. 非機能要件

- **内部仕様変更への耐性**: `~/.claude/` のファイル形式は内部仕様とみなし、変更されても
  クラッシュせず機能劣化（タイトルが出ない等）に留める。パース失敗は全てスキップ
- **パフォーマンス**: セッション JSONL（数十 MB になりうる）は全読みしない。
  末尾チャンク読み + 逆順走査で処理する
- **エージェント側データは読み取り専用**: `~/.claude/` 等には絶対に書き込まない
- **国際化（i18n）**: 最初から文言を外部化（Flutter の gen_l10n / ARB）し、日本語・英語の
  2 言語で提供する。フォールバックは英語。文言のハードコード禁止
- **サプライチェーン対策**: 依存パッケージは必要最小限。追加前に名前・公開日・メンテナを確認する。
  加えて次の 4 本柱を講じる（詳細は [design.md 8 章](./design.md#8-依存管理とサプライチェーン対策)）:
  1. リリースクールダウン — 公開から 7 日未満のバージョンを採用しない
     （pub 本体に機構がないため運用 + Renovate/Dependabot で強制）
  2. ビルド時コード実行の管理 — pub にインストールスクリプトはないが、
     build_runner・Flutter プラグインの native ビルドは審査対象にする
  3. 自動脆弱性チェック — CI に osv-scanner、リポジトリに Dependabot alerts
  4. ロックファイルの厳密運用 — `pubspec.lock` を commit し、
     CI では `dart pub get --enforce-lockfile`（content hash 検証込み）

## 5. アーキテクチャ制約（必ず守る）

- monorepo 構成: `packages/core`（pure Dart・UI 非依存）と `apps/desktop`（Flutter UI）に分離
- core に `AgentAdapter` 抽象インターフェースを定義し、エージェント差分をすべて adapter に閉じ込める。
  吸収する差分は次の 5 つ:
  1. セッション履歴の場所とパース
  2. セッションタイトル・メタデータ取得
  3. 復帰コマンドの組み立て
  4. 要約用ヘッドレス実行コマンド
  5. 新規セッション起動コマンドの組み立て（登録プロジェクト用、3.8）。`--resume` を付けない
     以外は復帰コマンドと同じ形
- 第 1 弾の adapter は Claude Code。ただしインターフェースは Claude 固有の概念に依存させない
- 全ロジックにユニットテスト

## 6. フェーズ計画と受け入れ基準

### フェーズ 1: core パッケージ（このフェーズだけ先に完成させる）

- 実装: 直近セッション一覧の取得 / メモ CRUD / 復帰コマンドの組み立て / 要約ヘッドレス実行
- まず実マシンの `~/.claude/history.jsonl` とセッション JSONL の実データ構造を調査してから実装する
- **受け入れ基準**: `dart test` が全パスし、CLI サンプル（一覧表示 → メモ登録 → 復帰コマンド出力）が動くこと

### フェーズ 2: Flutter デスクトップ UI（macOS 先行）

- 3.7 の常駐 UI を実装

### フェーズ 3 以降

- ライセンス選定（MIT / Apache-2.0 等）・README・CI（GitHub Actions）
- リポジトリ公開: private で開始し、公開準備（ライセンス・README・履歴の棚卸し）が
  整った時点で public 化する
- Windows/Linux 対応、マルチエージェント対応

### 進め方

- フェーズごとにレビューを挟む。フェーズ 1 完了時点で一度立ち止まって報告する
- 設計判断で迷ったら勝手に進めず選択肢を提示して質問する
- バージョン管理・改修フロー・リリース手順は [RELEASE.md](../../RELEASE.md) に従う

## 7. 将来課題

- メモへのセッション情報フルスナップショット抱き込み（現状はタイトル初期値と `projectPath` のみ）
- 要約の永続化（使ってみて必要なら `updatedAt` 付きでメモとは別ファイルに保存する案。現時点では見送り）
- メモ保存先の設定変更（現状は `~/.moost/v1/` 固定）
